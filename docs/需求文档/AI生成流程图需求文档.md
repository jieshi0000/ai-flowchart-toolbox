# AI 生成流程图 — 需求文档

**版本：** V1.0  
**状态：** 初稿  
**产品定位：** 面向学习者、产品人员和业务人员的轻量级在线流程图工具。用户输入自然语言需求后，系统生成可编辑的通用流程图，并支持画布调整和多格式导出。

---

## 1. 产品定位

AI 生成流程图是一个面向“描述即成图”的流程设计工具。用户不需要先学习复杂的绘图软件，只需用中文或英文描述业务步骤、判断条件和参与角色，系统即可生成结构化流程图，用户再在画布中完成少量修改并导出。

首版以单用户、单张通用流程图的稳定体验为主，优先支持教学练手、业务梳理、接口流程说明和简单审批流程。复杂标准图形、多人协作和图片识别作为后续扩展。

### 与 AI 应用广场的关系

AI 生成流程图作为 **第三方应用** 嵌入 AI 应用广场，用户通过广场发现、认证和使用本工具。

~~~text
AI 应用广场（主平台）                       AI 生成流程图（子应用）
┌──────────────────────┐      iframe        ┌──────────────────────────────┐
│ 应用详情页            │ ─────────────────► │ React + Ant Design 工作台      │
│ “立即使用”            │    postMessage    │ - 描述输入 / 节点画布         │
│                        │ ◄─────────────────┤ - Mermaid 查看 / 导出          │
│ 平台后端               │    AUTH_TOKEN     │ FastAPI 后端                  │
│ - 用户 / 钱包 / 订单    │                   │ - 文档与任务管理               │
│ - 临时 Token 签发       │                   │ - 模型网关与供应商轮询         │
│ - 用量扣费              │                   │ - 用量上报与结果存储           │
└──────────────────────┘                   └──────────────────────────────┘
~~~

- 广场负责用户认证、应用入口、积分或钱包和扣费。
- AI 生成流程图负责流程图生成、文档保存、画布编辑、导出、模型调用编排和结果存储。
- 两者通过 iframe、postMessage 和 HMAC 签名进行通信。

## 2. 与 AI 应用广场集成规范

### 2.1 iframe 嵌入

前端以 iframe 形式嵌入广场应用详情页。子应用保持单页面工作台形态，不额外打开新窗口或跳转独立站点。

### 2.2 认证流程

| 步骤 | 说明 |
|------|------|
| 1 | 用户在广场点击“立即使用”，进入 iframe 嵌入页 |
| 2 | 广场前端调用 GET /api/authorize?appId=ai-flowchart 获取临时 Token |
| 3 | 广场通过 iframe.contentWindow.postMessage 发送 AUTH_TOKEN |
| 4 | 子应用校验消息来源后保存 Token，后续请求携带 X-User-Token |

**postMessage 协议：**

| type | 说明 | payload |
|------|------|---------|
| ready | 子应用加载完成 | { type: "ready" } |
| AUTH_TOKEN | 广场传递认证信息 | { token, "X-User-Token": "...", appId: "ai-flowchart" } |
| THEME_CHANGED | 广场主题变化 | { theme: "light" or "dark", primaryColor, fontSize } |

### 2.3 用量上报

流程图生成任务仅在结构校验、渲染和结果保存均成功后上报用量。模型调用失败、超时、被取消或生成结果无效时不得扣费；已冻结积分必须按幂等规则退回。

~~~text
POST /api/usage/report
Headers:
  X-User-Token: tp_xxx
  X-App-Id: ai-flowchart
  X-Timestamp: 1783072800
  X-Nonce: nonce_xxx
  X-Signature: HMAC-SHA256(...)
Body:
{
  "taskId": "uuid",
  "taskType": "diagram_generate",
  "usage": 1,
  "costPoints": 1,
  "provider": "configured-provider",
  "model": "configured-model"
}
~~~

### 2.4 文件与结果存储

流程图文档、导出的 SVG、PNG、Mermaid 和 JSON 由子应用自行管理。开发和测试环境可使用 MinIO，生产环境建议使用云 OSS。广场不直接管理工具文件。

### 2.5 主题适配

子应用维护自身主题变量。接收到广场主题信息后，可同步亮色或暗色、主色和基础字号；画布网格、节点尺寸和操作密度保持稳定。

## 3. 功能模块

### 3.1 流程图工作台（基础底座）

所有功能共用描述输入区、模板区、中间画布、右侧属性面板和底部任务状态栏。任务成功后切换工具或收起面板不应丢失当前流程图。

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 描述输入 | 输入业务步骤、判断条件、参与角色和期望方向；支持中文和英文 | P0 |
| 示例模板 | 提供请假审批、用户注册、订单处理、登录校验等示例，可一键填入 | P0 |
| 画布预览 | 中央区域显示流程图，支持缩放、平移、适应画布和小地图 | P0 |
| 文档标题 | 自动生成标题，用户可修改 | P0 |
| 切换面板不丢图 | 当前文档、画布位置和未保存编辑保持 | P0 |
| 最近任务 | 展示当前用户近期生成记录，支持继续编辑、导出或重试 | P1 |

### 3.2 AI 流程图生成

系统将用户描述转换为受约束的流程图 JSON 中间结构，再生成 Mermaid 源码和节点画布数据。JSON 中间结构是唯一权威数据。

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 提示词校验 | 校验描述非空、长度、敏感或无关内容，并给出可理解提示 | P0 |
| 生成选项 | 支持自上而下、从左到右方向，以及简洁、标准、详细三个粒度 | P0 |
| 模型路由 | 支持系统自动选择或用户选择已启用模型；不展示 API Key | P0 |
| 结构化生成 | 模型必须返回节点、连线、标题和元数据，不直接信任自由文本 | P0 |
| 结构校验 | 校验节点类型、唯一标识、连线引用、标签长度和节点数量 | P0 |
| 重新生成 | 保留原图，新建任务生成新的候选文档 | P1 |
| 局部重新生成 | 选择节点或分支后要求 AI 重写局部流程 | P2 |

**首期节点类型：**

| 节点类型 | 说明 | 示例 |
|----------|------|------|
| start | 开始节点 | 用户发起申请 |
| end | 结束节点 | 流程结束 |
| process | 处理步骤 | 保存申请记录 |
| decision | 判断步骤 | 是否审批通过 |
| input_output | 输入或输出 | 填写申请表 |
| subprocess | 子流程 | 调用支付流程 |

### 3.3 节点画布编辑

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 节点操作 | 新增、删除、复制、拖拽、缩放和修改节点文本 | P0 |
| 连线操作 | 创建、删除、修改连线标签和判断条件 | P0 |
| 属性编辑 | 修改节点类型、标题、颜色、边框、位置和尺寸 | P0 |
| 字体策略 | 首期只使用随项目分发、许可可追溯的字体；中文默认思源黑体 Source Han Sans SC，英文与数字默认 Inter，禁止任意系统字体或用户上传字体 | P0 |
| 自动布局 | 一键根据方向重新布局，避免节点重叠 | P0 |
| 校验提示 | 提示孤立节点、缺少开始或结束节点、无效连线等问题 | P0 |
| 撤销与重做 | 记录当前文档的本地编辑历史 | P0 |
| 对齐工具 | 左右、上下、居中和等距分布 | P1 |

循环连线允许存在，用于表达“未通过后返回修改”等业务流程；系统只校验连线合法性，不将环路视为错误。

### 3.4 Mermaid 源码

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 源码查看 | 根据当前 JSON 中间结构生成 Mermaid 流程图源码 | P0 |
| 一键复制 | 复制 Mermaid 源码到剪贴板 | P0 |
| 同步更新 | 节点画布编辑后自动重新生成 Mermaid 源码 | P0 |
| 自由源码编辑 | 首期不支持任意 Mermaid 源码反向解析 | 非目标 |

### 3.5 模板与历史

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 内置模板 | 提供常见业务流程模板和示例描述 | P0 |
| 最近文档 | 按用户展示最近生成或编辑的流程图 | P1 |
| 保存个人模板 | 将当前流程图保存为个人模板 | P1 |
| 模板分类 | 审批、用户、订单、接口、学习等分类 | P1 |

### 3.6 导出与下载

| 功能 | 说明 | 优先级 |
|------|------|--------|
| SVG 导出 | 导出矢量图，适合文档和继续编辑 | P0 |
| PNG 导出 | 导出位图，支持透明或白色背景 | P0 |
| Mermaid 导出 | 导出 .mmd 文本文件 | P0 |
| JSON 导出 | 导出完整 DiagramDocument，便于备份和后续导入 | P0 |
| 字体一致性 | 前端预览、SVG 和 PNG 导出均使用同一套随项目打包的默认字体 | P0 |
| 下载安全 | 下载链接须鉴权或使用短期签名 URL | P0 |

### 3.7 模型与供应商状态

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 已启用模型列表 | 前端仅显示模型名称、供应商、能力和健康状态 | P0 |
| 自动路由 | 后端按能力、优先级、可用性和限流状态选择模型 | P0 |
| 手动选择 | 用户可选择系统允许使用的模型；选择不可用模型时禁止提交 | P0 |
| 服务降级 | 仅在已启用且能力匹配的供应商之间切换，并记录原因 | P1 |
| API 配置 | 仅由服务端运维配置，普通用户没有 API Key 输入框 | P0 |

## 4. 通用需求

### 4.1 输入与文档规则

| 项目 | 规则 |
|------|------|
| 描述长度 | 1 至 4000 个字符 |
| 文档标题 | 最长 100 个字符 |
| 节点数量 | 首期单张图最多 50 个节点 |
| 连线数量 | 首期单张图最多 100 条连线 |
| 节点标签 | 最长 120 个字符，禁止 HTML 和脚本内容 |
| 默认字体 | 中文使用思源黑体 Source Han Sans SC，英文与数字使用 Inter；两者均以 SIL Open Font License 1.1 发布，可用于本项目的免费商用分发 |
| 字体来源 | Inter、思源黑体的字体文件、版本和 OFL 许可证随项目或 Worker 镜像保存；不依赖 Windows 宋体 SimSun、Times New Roman 或其他宿主机系统字体 |
| 导出格式 | SVG、PNG、Mermaid、JSON |
| 文档有效期 | 默认 30 天；导出文件默认 24 小时 |
| 数据访问 | 用户只能访问自己的文档、任务和下载文件 |

### 4.2 页面状态

前后端任务状态字段使用以下固定值，页面根据状态展示对应中文文案：

~~~text
waiting
submitting
provider_queued
provider_processing
validating
rendering
success
failed
canceled
expired
~~~

| 状态 | 表现 |
|------|------|
| 未输入 | 显示示例描述和模板，生成按钮禁用 |
| 提交中 | 生成按钮 loading，底部显示“正在创建任务” |
| 排队中 | 显示“任务已排队”，可取消 |
| 模型处理中 | 显示阶段、进度或等待提示，前端不直接访问供应商 |
| 校验或渲染中 | 显示“正在校验流程图结构”或“正在渲染画布” |
| 成功 | 中央显示结果，提供编辑和导出入口 |
| 失败 | 展示可理解错误原因、任务详情和重试按钮 |
| 已取消或已过期 | 提示重新生成或从最近文档恢复 |

### 4.3 刷新、离开与轮询

- 创建任务后，前端立即保存 taskId 和浏览器会话关联 ID；刷新页面后先通过本系统任务接口恢复状态，本地缓存丢失时按当前登录用户恢复最近未结束任务。
- 前端优先订阅本系统 SSE 任务事件；SSE 不可用时每 2 秒轮询本系统任务接口。
- 前端不得直接轮询模型供应商 API，也不得保存供应商任务凭据。
- 用户离开页面前，如有未保存的画布编辑或运行中的任务，应给出确认提示。
- 长任务允许后台继续处理，用户回到页面后可继续查看结果。

### 4.4 异步任务与供应商轮询

| 项目 | 规则 |
|------|------|
| 本地任务响应 | 创建任务接口 1 秒内返回 taskId 或明确错误 |
| 供应商提交 | Worker 调用供应商 submit，并保存 providerRequestId |
| 首次轮询 | 默认提交后 3 秒执行，供应商有 Retry-After 时优先遵守 |
| 退避策略 | 间隔指数增长，最大不超过 15 秒 |
| 总超时 | 默认 10 分钟，按供应商和模型可配置 |
| 网络错误 | 网络错误、限流和 5xx 可按规则重试 |
| 终态错误 | 参数错误、内容安全拒绝、余额不足等不重试 |
| 幂等性 | 提交和用量上报均使用幂等键，避免重复任务和重复扣费 |
| 取消 | 本地任务取消时尽力取消供应商任务；无论供应商取消是否成功，最终都要结束本地任务并退回未确认积分 |

### 4.5 异常处理

| 场景 | 文案要求 |
|------|----------|
| 描述为空 | “请先输入需要生成的流程说明” |
| 描述过长 | “描述超过当前长度限制，请精简后重试” |
| 模型未配置 | “当前没有可用的生成模型，请稍后再试” |
| 模型限流 | “当前生成请求较多，任务已排队或请稍后重试” |
| 模型超时 | “生成耗时较长，任务已超时，请重试或更换模型” |
| 结构校验失败 | “生成结果不符合流程图规则，请重新描述流程后再试” |
| Mermaid 渲染失败 | “流程图渲染失败，已保留任务记录，可尝试重新生成” |
| 导出失败 | “导出失败，请稍后重试” |
| 积分不足 | “当前积分不足，请充值或选择可用功能” |

### 4.6 代码规范

- 前端使用 React、TypeScript、Vite、Ant Design、React Router、Zustand、React Flow 和 Mermaid。
- 后端优先使用 FastAPI、SQLAlchemy async、PostgreSQL、Redis 和异步任务队列。
- 所有模型调用封装在 Provider Gateway 内；优先复用 OpenAI 兼容协议，非兼容 API 使用独立适配器。
- 接口仅使用 GET 和 POST，返回统一 Result<T>。
- 所有生成类操作创建异步任务，普通 HTTP 请求不等待模型完成。
- API Key、签名密钥和供应商原始错误只允许留在服务端，不下发前端。

## 5. 数据库需求

### 5.1 实体关系

~~~text
用户 user_id
  ├── 流程图文档 flowchart_document
  │     ├── JSON 中间结构 diagram_data
  │     └── Mermaid 源码 mermaid_source
  ├── 任务 flowchart_task
  │     ├── 供应商任务 provider_request_id
  │     └── 输出文件 flowchart_file
  ├── 模板 flowchart_template
  ├── 积分流水 flowchart_quota_log
  ├── 模型调用日志 flowchart_provider_call
  └── 埋点事件 flowchart_event
~~~

### 5.2 业务表

| 表名 | 说明 |
|------|------|
| flowchart_document | 流程图文档表，保存标题、方向、DiagramDocument JSON、Mermaid 源码和版本信息 |
| flowchart_task | 异步任务表，保存本地状态、供应商任务、轮询计划、结果、错误和耗时 |
| flowchart_file | 文件表，保存 SVG、PNG、Mermaid、JSON 等导出文件路径和元信息 |
| flowchart_template | 模板表，保存内置和个人模板的 JSON 配置 |
| flowchart_quota_log | 积分流水表，记录冻结、确认扣减和退款 |
| flowchart_provider_call | 模型调用日志表，记录供应商、模型、协议、请求 ID、轮询和成本 |
| flowchart_event | 埋点事件表，记录生成、编辑、导出和下载行为 |

### 5.3 数据清理

| 数据 | 默认有效期 | 清理策略 |
|------|------------|----------|
| 导出文件 | 24 小时 | 定时删除对象存储文件和数据库记录 |
| 任务记录 | 7 天 | 保留任务状态和错误信息，供用户重试和排查 |
| 流程图文档 | 30 天 | 到期前提示用户续存或导出；后端按策略清理 |
| 模型调用日志 | 90 天 | 用于成本统计、轮询问题排查和供应商质量评估 |
| 埋点事件 | 180 天 | 用于产品分析 |

## 6. 验收标准

### 6.1 业务验收

| 项目 | 验收标准 |
|------|----------|
| 描述生成 | 输入有效流程描述后，可生成包含节点、连线、标题和 Mermaid 源码的流程图 |
| 画布编辑 | 支持修改节点、连线、位置和属性，修改后 Mermaid 源码同步更新 |
| 自动布局 | 在 50 个节点以内可完成布局，节点不明显重叠 |
| 导出 | 可下载 SVG、PNG、Mermaid 和 JSON 文件 |
| 模型选择 | 仅显示服务端已启用模型，前端无任何密钥字段 |
| 异步任务 | 提交后快速返回 taskId，状态可从排队、处理中进入成功、失败或取消 |
| 刷新恢复 | 页面刷新后可恢复未完成或已完成任务状态，不重复提交模型请求 |
| 异常文案 | 所有常见异常均有可理解的中文说明 |

### 6.2 性能验收

| 项目 | 标准 |
|------|------|
| 首屏加载 | 工作台首屏在正常网络下 3 秒内可交互 |
| 创建任务 | 点击生成后 1 秒内返回 taskId 或明确错误 |
| 前端反馈 | 提交后 1 秒内显示排队或处理状态 |
| 供应商轮询 | 后端遵守初始 3 秒、最大 15 秒的退避规则，不出现忙轮询 |
| 任务恢复 | 刷新后可恢复任务状态和结果入口 |
| 画布操作 | 50 个节点、100 条连线以内可正常缩放、拖拽和编辑 |

### 6.3 安全验收

| 项目 | 标准 |
|------|------|
| 用户隔离 | 用户只能访问自己的文档、任务和文件 |
| 密钥安全 | API Key、HMAC 密钥和供应商密钥不出现在前端、接口响应或普通日志中 |
| 模型安全 | 模型输出仅作为 JSON 数据处理，不执行其中的代码或脚本 |
| Mermaid 安全 | 节点标签进行转义，渲染使用安全配置，不执行 HTML 或脚本 |
| 字体合规 | 预览与导出只使用许可可追溯的项目内 Inter 与思源黑体；导出 Worker 不依赖宿主机系统字体 |
| 下载安全 | 下载链接需要鉴权或短期签名 |
| 扣费幂等 | 重试、刷新和网络超时不导致重复冻结、扣费或上报 |
