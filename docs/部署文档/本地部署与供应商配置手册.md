# 本地部署与供应商配置手册

本文档用于在 Windows PowerShell 上运行 AI 流程图工具箱的完整本地环境，并配置 DeepSeek 官方 Provider。范围仅限本地开发，不替代生产部署、密钥轮换或外部应用广场联调。

## 1. 前置条件

- Docker Desktop 已启动，`docker compose version` 可正常执行。
- Node.js 与 pnpm 仅在需要本机运行前端检查时使用；完整本地环境由 Docker Compose 构建。
- 工作目录为 `D:\code_file\ai-flowchart-toolbox\ai-flowchart-toolbox`。

```powershell
Set-Location D:\code_file\ai-flowchart-toolbox\ai-flowchart-toolbox
docker compose version
```

## 2. 本地私有配置

本地完整环境读取受 Git 忽略的 `docker-compose.local.env`。它是 Compose 的初始化输入：

- `LOCAL_POSTGRES_*` 创建本地 PostgreSQL，并用于组装后端连接串。
- `LOCAL_MINIO_*` 创建本地 MinIO 根账号。
- `LOCAL_DEEPSEEK_API_KEY` 只映射为后端、Celery Worker 和 Beat 容器内的 `DEEPSEEK_API_KEY`。
- 可选端口变量为空时使用 Compose 中的默认端口；已有本地服务冲突时才填写其他端口。

首次使用时复制示例；已有文件时不要覆盖：

```powershell
if (-not (Test-Path docker-compose.local.env)) {
  Copy-Item docker-compose.local.env.example docker-compose.local.env
}
```

填写示例中的必填 `LOCAL_*` 值后保存。不要把真实密钥、密码或 `CONFIG_KEY` 写入可提交文件，也不要将任何密钥写入 `VITE_*` 前端变量。

Provider 清单同样使用本机私有文件。首次使用可从示例生成：

```powershell
if (-not (Test-Path backend\config\providers.local.json)) {
  Copy-Item backend\config\providers.example.json backend\config\providers.local.json
}
```

`backend/config/providers.local.json` 由 Compose 以只读方式挂载到后端、Worker 和 Beat。提交前可只检查忽略规则，不读取或输出文件中的敏感值：

```powershell
git check-ignore -v docker-compose.local.env backend/config/providers.local.json
```

## 3. 启动与访问

```powershell
docker compose --env-file docker-compose.local.env -f docker-compose.local.yml up -d --build
docker compose --env-file docker-compose.local.env -f docker-compose.local.yml ps
Invoke-RestMethod http://localhost:10105/api/public/health
```

默认地址如下；若填写了对应的端口变量，以实际 Compose 端口为准。

| 服务 | 默认地址 |
| --- | --- |
| 工作台 | `http://localhost:20105/flowchart/workbench` |
| 后端健康检查 | `http://localhost:10105/api/public/health` |
| 后端 OpenAPI | `http://localhost:10105/docs` |
| MinIO Console | `http://localhost:9001` |

工作台使用本地 `admin` 演示账号登录。登录后，页头显示“模型服务”且模型下拉框出现 `deepseek-v4-flash` 时，说明 Provider 配置已被安全加载；页面不会显示 Provider ID、Base URL 或 API Key。

## 4. DeepSeek 官方 Provider

示例清单提供两个独立协议配置，二者都使用 `deepseek-v4-flash` 和 `DEEPSEEK_API_KEY`：

| Provider ID | 协议 | 用途 |
| --- | --- | --- |
| `deepseek-official-chat` | `openai_chat_completions` | 调用 `/chat/completions`，默认优先级更高。 |
| `deepseek-official-responses` | `openai_responses` | 调用无状态 `/responses`，用于协议验收与可切换路由。 |

两项的 `displayName` 与 `model` 均为 `deepseek-v4-flash`。前端会按显示名合并为一个模型选项，自动路由由后端按优先级选择具体协议；任务创建后会保存实际 Provider，执行过程中不会静默换用其他 Provider。

真实联调只提交不含业务敏感信息的短描述。配置中的 `maxOutputTokens` 是输出上限，`taskTimeoutSeconds` 是单次任务总超时。Chat 与 Responses 均使用非流式请求，前端的实时状态来自本地任务 SSE，SSE 不可用时每 2 秒轮询一次。

## 5. 日常运维

查看应用日志：

```powershell
docker compose --env-file docker-compose.local.env -f docker-compose.local.yml logs --tail=200 backend-api celery-worker celery-beat
```

正常停止和恢复服务会保留 PostgreSQL、Redis 和 MinIO 数据：

```powershell
docker compose --env-file docker-compose.local.env -f docker-compose.local.yml stop
docker compose --env-file docker-compose.local.env -f docker-compose.local.yml start
```

不要为排查普通启动或 Provider 问题使用 `docker compose down -v`。它会删除本地卷，造成流程图、任务和导出文件丢失。

Beat 每分钟执行任务补偿。仅生成类任务在 `waiting` 或 `submitting` 且创建超过一小时、尚未完成供应商提交时，才会被收敛为 `expired`，页面会提示重新生成；SVG、PNG、Mermaid、JSON 导出任务仍由独立 Chromium/文件导出恢复逻辑处理。

## 6. 常见问题

### 模型服务不可用

1. 确认 `docker-compose.local.env` 中 `LOCAL_DEEPSEEK_API_KEY` 已配置，但不要在终端回显它。
2. 确认 `backend/config/providers.local.json` 存在且未被误提交。
3. 重建后端相关服务，再查看 Worker 日志中的安全错误码：

```powershell
docker compose --env-file docker-compose.local.env -f docker-compose.local.yml up -d --build backend-api celery-worker celery-beat
docker compose --env-file docker-compose.local.env -f docker-compose.local.yml logs --tail=200 celery-worker
```

`provider_unavailable`、限流和认证失败在工作台中会映射为中文提示；不要从前端错误信息推断或暴露私有 Provider 配置。

### 刷新后画布看似为空

已保存文档的 ID 会保存在浏览器本地上下文中。刷新后，工作台会自动加载该文档并切换到“编辑”模式。若浏览器本地数据已被清除，可重新生成，或通过业务接口按当前登录用户查询可恢复任务。

### 导出文件无法下载

先确认导出任务为“导出已完成”，再点击“下载文件”。四种格式均通过同一个鉴权下载接口返回附件；JSON 是正常文件格式，不应被当成 API 错误。下载失败时检查后端和 Worker 日志，不要直接暴露 MinIO 访问凭据。

## 7. 交付前检查

```powershell
Set-Location backend
$env:APP_ENV = 'test'
$env:DATABASE__URL = 'postgresql+asyncpg://test:test@127.0.0.1:5432/test_db'
$env:REDIS__URL = 'redis://127.0.0.1:6389/0'
$env:MINIO__SECRET_KEY = 'unit-test-secret'
uv run pytest tests/unit/ -q

Set-Location ..\frontend
pnpm typecheck
pnpm build

Set-Location ..
git diff --check
git status --short
```

完整集成测试需要按 `backend/tests/docker-compose.yml` 启动专用测试 PostgreSQL 和 Redis。测试服务默认占用 `5432` 和 `6389`，与本地开发服务端口冲突时，应先调整或停止冲突服务，不要删除本地开发卷。
