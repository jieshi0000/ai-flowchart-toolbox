# 数据库规范

## 1. 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 表名 | 小写 + 下划线 + 单数形式 | `user`、`wallet_transaction` |
| 字段名 | 小写 + 下划线 | `user_id`、`app_name`、`created_at` |
| 主键名 | 统一命名为 `id` | `id UUID` |
| 外键名 | `关联表名_id`（单数） | `user_id`、`category_id` |
| 索引名 | `idx_表名_字段` | `idx_user_mobile` |
| 唯一索引 | `uk_表名_字段` | `uk_user_email` |

## 2. 常见字段长度规范

| 字段用途 | 类型 | 长度 | 示例 |
|---------|------|------|------|
| 名称类 | VARCHAR | 50-100 | `name VARCHAR(100)` |
| 枚举编码 | VARCHAR | 20 | `status VARCHAR(20)` |
| 手机号 | VARCHAR | 20 | `phone VARCHAR(20)` |
| 邮箱 | VARCHAR | 100 | `email VARCHAR(100)` |
| URL | VARCHAR | 500 | `icon_url VARCHAR(500)` |
| 详细描述 | TEXT | - | `description TEXT` |
| 金额/余额 | DECIMAL | (16,4) | `amount DECIMAL(16,4)` |
| 价格 | DECIMAL | (10,4) | `price DECIMAL(10,4)` |
| 主键/外键 | UUID | - | `id UUID PRIMARY KEY` |

## 3. 枚举值规范

- 格式：**英文大写 + 下划线**（如 `ACTIVE`、`PENDING`）
- 不使用数据库 ENUM 类型，应用层维护，数据库存 VARCHAR 或 INT
- 建议定义常量或枚举，但不强制

## 4. 字段类型速查表

| 用途 | PG 类型 | Python 类型 |
|------|---------|------------|
| 主键 | UUID | `uuid.UUID` |
| 外键 | UUID | `uuid.UUID` |
| 金额 | `DECIMAL(16,4)` | `Decimal` |
| 价格 | `DECIMAL(10,4)` | `Decimal` |
| 状态/枚举 | `VARCHAR(20)` | `str` |
| 日期 | `DATE` | `datetime.date` |
| 时间 | `TIMESTAMP` | `datetime.datetime` |
| 标签列表 | `TEXT[]` | `list[str]` |
| 评分列表 | `INTEGER[]` | `list[int]` |
| 扩展属性 | `JSONB` | `dict` |

## 5. 审计字段

所有表必须包含 `id` 和 `created_at`：

```sql
id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
created_at  TIMESTAMP   NOT NULL DEFAULT now()
```

应用层生成 ID 使用 `uuid_utils.uuid7()`（UUID v7，时间有序，对齐 Java 的 `IdUtil.uuid7()`）。

可选添加 `updated_at`。

## 6. 外键约束

- **不使用数据库外键约束**
- **应用层保证数据一致性**

## 7. 数据库迁移规范

### 7.1 文件命名与位置

| 类型 | 命名格式 | 位置 | 说明 |
|------|---------|------|------|
| 结构迁移（DDL） | `V{n}__{描述}.sql` | `db/` | 版本号递增，不可修改已执行的脚本 |
| 种子数据（DML） | `V{n}__{描述}.sql` | `db/` | 与 DDL 同目录；脚手架示例种子可按需整文件删除 |

### 7.2 执行策略

| 环境 | 行为 | 控制方式 |
|------|------|---------|
| 生产（默认） | **不执行** | `DATABASE__AUTO_MIGRATE=false` |
| 本地开发 | 自动执行 | `.env.local` 设 `DATABASE__AUTO_MIGRATE=true` |
| 测试 | 自动执行 | `.env.test` 设 `DATABASE__AUTO_MIGRATE=true` |

```bash
# 查看待执行迁移
uv run python migrate.py --check

# 执行待处理迁移
uv run python migrate.py

# 查看版本状态
uv run python migrate.py --status

# 生产容器内（镜像含 db/ + migrate.py；需已 compose up 或至少能解析 env）
docker compose run --rm backend uv run python migrate.py
```

执行失败会回滚当前迁移，阻断应用启动，日志会标明具体哪个文件失败。

### 7.3 登记表

自动创建 `schema_migrations` 表：

```sql
version     INTEGER PRIMARY KEY,
filename    VARCHAR(255) NOT NULL,
checksum    VARCHAR(64) NOT NULL,
executed_at TIMESTAMP NOT NULL DEFAULT now()
```

- checksum 防篡改：已执行的文件被修改后会检测到并报错
- 幂等性：再次运行不会重复执行已登记的版本

## 8. SQLAlchemy Model 规范

- 所有 DB model 继承 `BaseDBModel`（定义在 `models/base.py`）
- 使用 SQLAlchemy 2.0 typed mapper 风格：`Mapped[type]` + `mapped_column()`
- DB model 和 API schema 分离：model 在 `models/`，schema 在 `schemas/`

```python
# models/base.py
class BaseDBModel(Base):
    __abstract__ = True
    id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True, default=lambda: uuid_utils.uuid7())
    created_at: Mapped[datetime] = mapped_column(TIMESTAMP, nullable=False, server_default=func.now())
    updated_at: Mapped[datetime] = mapped_column(TIMESTAMP, nullable=False, server_default=func.now(), onupdate=func.now())

# models/demo_product.py
class DemoProduct(BaseDBModel):
    __tablename__ = "demo_product"
    name: Mapped[str] = mapped_column(String(100), nullable=False)
    price: Mapped[float] = mapped_column(Numeric(16, 4), nullable=False, default=0)
```
