# 接口设计规范

### HTTP 方法规范

**重要**: 为兼容企业网关、防火墙、CDN，本项目**只使用 GET 和 POST**，不使用 PUT/DELETE/PATCH。

**统一用语义化路径表达操作：**

| 操作 | 传统 RESTful | 本项目规范 |
|------|-------------|-----------|
| 创建 | POST /products | POST /products/create |
| 查询列表 | GET /products | GET /products/list |
| 查询详情 | GET /products/1 | GET /products/get?id=1 |
| 更新 | PUT /products/1 | POST /products/update?id=1 |
| 删除 | DELETE /products/1 | POST /products/delete?id=1 |
| 分页 | GET /products?page=1 | GET /products/page?pageNum=1&pageSize=10 |

**原因**：
- 企业安全策略默认只放行 GET/POST
- 避免 CORS 预检请求开销
- 兼容各类网关/代理/防火墙

### 参数传递规范

| 参数类型 | 传递方式 | 示例 |
|---------|---------|------|
| **敏感数据**（密码、token） | **请求体 JSON** | `POST /auth/login` + `{"phone":"xxx","password":"xxx"}` |
| 复杂对象（创建/更新） | **请求体 JSON** | `POST /products/create` + `{"name":"xxx","price":99.9}` |
| 简单查询参数（ID等） | **查询参数** | `GET /products/get?id=1` |
| 分页参数 | **查询参数** | `GET /products/page?pageNum=1&pageSize=10` |

**禁止**：敏感数据通过 URL 参数传递、使用路径参数 `/{id}`。

### JSON 字段命名

Python 代码内部全部用 **snake_case**（符合 Python 规范）。

JSON 输出通过配置 `APP__JSON_CAMEL_CASE` 切换（嵌套键用 `__`，与 `env_nested_delimiter` 一致）：
- `true`（**默认**）：输出 camelCase，与 Java / 前端对齐
- `false`：输出 snake_case，按需关闭

在 `.env` / 环境覆盖中设置：
```bash
APP__JSON_CAMEL_CASE=true     # 默认；与 Java 对齐
APP__JSON_CAMEL_CASE=false    # 需要 snake_case 时再关
```

默认开启后，`view_count` → `viewCount`，`created_at` → `createdAt`，全局自动转换，不需要在每个 Schema 里单独处理。

### 统一响应格式

所有接口必须返回 `Result[T]`：

```json
{
    "code": 200,
    "data": { ... },
    "message": "操作成功",
    "timestamp": 1717912345678
}
```

| 场景 | code | HTTP 状态码 |
|------|------|------------|
| 成功 | 200 | 200 |
| 业务异常 | 自定义（400/404/10001 等） | 200 |
| 参数校验失败 | 400 | 200 |
| 未捕获异常 | 500 | 500 |

### 分页接口规范

请求参数（查询参数）：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| pageNum | int | 1 | 页码，从 1 开始 |
| pageSize | int | 10 | 每页条数 |
| orderBy | str | null | 排序字段 |
| sort | str | null | 排序方向：asc/desc |

响应结构：

```json
{
    "code": 200,
    "data": {
        "pageNum": 1,
        "pageSize": 10,
        "pages": 2,
        "total": 15,
        "records": [ ... ]
    },
    "message": "操作成功",
    "timestamp": 1717912345678
}
```
